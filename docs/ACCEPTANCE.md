## Найденный и исправленный дефект

### Дефект: беззвучное обновление с посторонними файлами уходило в подпапку

**Сценарий.** Установлена версия 1.0.0 без `.max-install-manifest`. В папку
установки добавлены пользовательские файлы. Запущено обновление 1.0.2 в
`/silent` режиме.

**Ожидаемый результат.** Существующая установка обновляется на месте;
посторонние файлы сохраняются, подпапка `MAX` не создаётся.

**Фактический результат до исправления.** `HasForeignFiles` считал папку
«чужой» из-за пользовательских файлов, и silent-установщик создавал
`<папка>\MAX`, оставляя старую 1.0.0 без обновления.

**Исправление.** Добавлена проверка `IsExistingInstall(dir)` по
`FileVersionInfo` (`ProductName = MAX Messenger`, `CompanyName = MAX`).
Для существующей установки `HasForeignFiles` возвращает `false`, поэтому
обновление идёт на месте. Проверка интерфейса использует то же правило.

**Повторная проверка.** После исправления v1.0.0 обновилась до 1.0.2.0
на месте, манифест создан, `foreign.txt` и `foreign-dir\note.txt` сохранены,
подпапка `MAX` не появилась. Результат: **пройден**.

## Детали ключевых проверок

### Обычный пользователь

Установщик запускался от имени временных пользователей `MaxTest102`/`MaxTest102b`
через `Start-Process -Credential -LoadUserProfile`. Установка прошла в
`C:\Users\MaxTest102\AppData\Local\Programs\MAX`, запроса UAC не было.
`Max.exe /policy-test` завершился с кодом 0. Удаление через `Uninstall.exe`
завершилось с кодом 0, папка установки удалена.

### Профиль и повышенные права

Смоделирован процесс, который выполняется после подтверждения UAC:
`Uninstall.exe /uninstall /silent /dir=... /deletedata /profiledir="C:\Users\MaxTest102\AppData\Local\MAX Messenger"`.
Профиль другого пользователя был удалён. Повторная проверка с `/keepdata`
оставила профиль на месте. Это подтверждает передачу пути к профилю
пользователя, начавшего удаление.

### Откат

Обновление запускалось при открытом с `FileShare.None` файле
`Microsoft.Web.WebView2.WinForms.dll`. Установщик вернул код 2,
`Max.exe` остался версии 1.0.2.0, хеш не изменился, `/policy-test` после
отката прошёл.

### Горячие клавиши

После активации окна отправлены `Ctrl+R`, `Alt+Left`, `Alt+Right`, `Ctrl+=`,
`Ctrl+-`, `Ctrl+0`, `F11`, `Esc`. В `app.log` появились записи
`Hotkey action: reload/back/forward/zoomIn/zoomOut/zoomReset/fullscreen/exitFullscreen`.
`F11` и `Esc` изменили и восстановили стиль окна.

### Подпись

`Get-AuthenticodeSignature` для `MaxSetup.exe`, установленного `Max.exe` и
`Uninstall.exe` возвращает `Status = UnknownError`, `SignerCertificate`
присутствует, `TimeStamperCertificate` присутствует. Это ожидаемо для
самоподписанного сертификата. Для критерия «Valid на чистой Windows» нужен
сертификат доверенного ЦС; без него сборка остаётся тестовой.

## Вывод

Автоматизированные обязательные сценарии установки, обновления с 1.0.0,
отката, удаления, защиты посторонних файлов и junction-ссылок, проверки
подписи загрузчика WebView2, политики навигации, горячих клавиш и
восстановления окна пройдены. Найден и исправлен дефект обновления в папке с
посторонними файлами.

Для финального публичного релиза остаются блокирующими:

1. доверенный сертификат подписи кода (сейчас тестовая подпись);
2. ручная проверка входа по QR/номеру, выхода, камеры/микрофона и скачивания
   файлов на тестовом аккаунте MAX;
3. проверка на Windows 11, x86 и ARM64;
4. интерактивная проверка отмены UAC.

До закрытия этих пунктов версия 1.0.2 публикуется как тестовая.
